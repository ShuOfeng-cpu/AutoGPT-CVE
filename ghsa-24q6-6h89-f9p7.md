# GHSA-24q6-6h89-f9p7: Hardcoded Default JWT Secret Enables Complete Authentication Bypass

## 1. Overview

AutoGPT Platform ships with a publicly known, hardcoded default JWT verification key (your-super-secret-jwt-token-with-at-least-32-characters-long) in both backend/.env.default and autogpt_platform/.env.default.Because HS256 is a symmetric algorithm, any attacker who knows the secret can forge valid JWTs for any user ID or admin role — bypassing all authentication and authorization in the platform without any user interaction.

## 2. Technical Details

### 2.1 Root Cause

The affected authentication boundary did not enforce the expected verifier for the stored webhook or object. The vulnerable component is Hardcoded Default JWT Secret / JWT Secret (`backend/.env`).

### 2.2 Affected Code

The advisory identifies the following affected file(s):

- `backend/.env`
- `autogpt_platform/.env`

### 2.3 Exploitation Path

Any self-hosted AutoGPT Platform deployment using the default.env is affected. An unauthenticated attacker can: Impersonate any user — read/modify agent graphs, execution history, stored credentials, and workspace files Forge admin tokens — access all admin-only routes, manage credits, configure rate limits, and expose system internals Trigger arbitrary agent executions billed to any user Mass-drain user credit balances

## 3. Vulnerable Code Pattern

The vulnerable pattern is located in `backend/.env` and is tied to the Hardcoded Default JWT Secret / JWT Secret (`backend/.env`) functionality described above.

## 4. The Fix

The issue is fixed in `0.8.0`.

Linked fix material:

- https://github.com/Significant-Gravitas/AutoGPT/pull/14519
