## 1. Overview

- Vulnerability Type: Credential Leakage - Affected Location: classic/forge/forge/components/git_operations/git_operations.py:102 - Trigger Scenario: clone_repository sends configured GitHub credentials to attacker-controlled URLs

## 2. Technical Details

### 2.1 Root Cause

The vulnerable behavior comes from forwarding or recording credentials outside the intended trust boundary. The affected component is GitHub credentials (`classic/forge/forge/components/git_operations/git_operations.py`).

### 2.2 Affected Code

The advisory identifies the following affected file(s):

- `classic/forge/forge/components/git_operations/git_operations.py`

The advisory/source text also names the following relevant symbols or runtime objects:

- `api_key`
- `split_url`

### 2.3 Exploitation Path

An attacker can cause AutoGPT to send a request or follow a redirect to a destination outside the intended trust boundary, while sensitive headers, cookies, or credentials remain attached to the request.

### 2.5 Source Evidence

#### Root-cause evidence

`clone_repository(self, url, clone_path)` accepts attacker-controlled `url` (`classic/forge/forge/components/git_operations/git_operations.py:86`).
It then reads configured credentials and embeds them into the URL:

- `api_key = self.config.github_api_key.get_secret_value()` (`classic/forge/forge/components/git_operations/git_operations.py:97-100`)
- `auth_repo_url = f"//{self.config.github_username}:" f"{api_key}@".join(split_url)` (`classic/forge/forge/components/git_operations/git_operations.py:102-104`)

Finally, it calls `Repo.clone_from(url=auth_repo_url,.)` (`classic/forge/forge/components/git_operations/git_operations.py:106`) without host restriction, so credentials are sent to attacker-selected remote hosts.

#### Implementation evidence

1. Source (user-controlled input)

- Attacker controls repository URL passed to:

`clone_repository(self, url: str, clone_path: Path)`
Location: `classic/forge/forge/components/git_operations/git_operations.py:86`

1. Data flow

- URL is split and reconstructed with configured credentials:

`split_url = url.split("//")`: `classic/forge/forge/components/git_operations/git_operations.py:96`
`auth_repo_url =.`: `classic/forge/forge/components/git_operations/git_operations.py:102-104`
- The `@validate_url` decorator (`classic/forge/forge/components/git_operations/git_operations.py:85`) only performs syntax checks and does not restrict destination host trust.

1. Sink (dangerous execution point)

- Credential-bearing URL is used in outbound git transport:

`Repo.clone_from(url=auth_repo_url, to_path=clone_path)`
Location: `classic/forge/forge/components/git_operations/git_operations.py:106`
- Git authentication data is therefore sent to the attacker-controlled repository endpoint.

#### Exploitation preconditions

1. The attacker can supply input that influences sensitive data handling or outbound requests.
2. Sensitive tokens/files/metadata are reachable from the affected code path.
3. Trust boundary checks for data exposure are missing or weak.

## 3. Vulnerable Code Pattern

The vulnerable pattern is carrying credentials across a trust boundary without binding them to the intended destination or without redacting them before logging.

## 4. The Fix

Fix strategy:

- Upgrade AutoGPT to `0.6.66` or a later release containing the patch.
- Apply the source-stated remediation: 1.
- Apply the source-stated remediation: Never inject secrets into arbitrary user-provided clone URLs. 2.
- Apply the source-stated remediation: Restrict clone targets to trusted GitHub hosts. 3.
- Apply the source-stated remediation: Use secure credential mechanisms (helper/askpass/per-host auth config) instead of URL credentials.
- Bind credentials and protected headers to the intended destination host before forwarding requests.
- Strip credentials on cross-origin redirects or when the destination host no longer matches the trusted origin.
- Redact sensitive values from logs and error propagation paths.

Validation and regression checks:

- A redirect to a different host should not receive the original `Authorization`, `Proxy-Authorization`, cookie, or protected header values.
- A same-origin redirect should preserve only the headers that are still valid for the redirected request.
- Logs and propagated errors should not expose token, cookie, API key, or credential values.

Operational follow-up:

- Inventory self-hosted AutoGPT deployments and confirm whether their running version falls inside the affected range.
- If an immediate upgrade is not possible, backport the same validation, authorization, or dependency constraint shown by the linked fix material.
- Rotate any credentials, tokens, cookies, or encrypted material that may have crossed the affected trust boundary.
