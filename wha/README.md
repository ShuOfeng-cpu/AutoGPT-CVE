# OpenClaw Vulnerability Records

The vulnerability records are grouped by OpenClaw component in subfolders. See [COMPONENT_CLASSIFICATION.md](./COMPONENT_CLASSIFICATION.md) for the initial N-02 through N-11 mapping and its limits.

This directory contains one English-language Markdown record for every public repository security advisory in `openclaw/openclaw` as of `2026-10-28` (Asia/Shanghai). Each record follows the same 21-field schema. CVE identifiers are reconciled across the repository advisory API, CVE List V5 CNA references, and GitHub Global Advisory data.

Files with a confirmed CVE mapping are named `CVE-YYYY-NNNN.md`; when one CVE explicitly covers multiple GHSAs, additional records use `CVE-YYYY-NNNN__GHSA-xxxx-xxxx-xxxx.md`. Records without a confirmed CVE retain their `GHSA-xxxx-xxxx-xxxx.md` filename.

## Evidence Rules

- The GitHub repository-advisory API is the canonical inventory and source for GHSA identifiers, vendor narrative, affected/fixed version ranges, and repository publication timestamps.
- CVE.org and NVD keyword results are used only to discover candidate CVE IDs. A filename mapping requires the repository API, an explicit CVE List V5 CNA GitHub Security Advisory URL, or an exact GHSA-ID join to the GitHub global-advisory API that CNA evidence does not contradict. Keyword or title similarity is never used.
- When multiple published CVE IDs identify one GHSA, the GitHub-linked CVE is used for the filename and every additional CVE, score, CWE, date, and reference remains visible in the record.
- When one CVE explicitly names multiple GitHub Security Advisories, its primary record uses `CVE-ID.md` and each additional advisory uses `CVE-ID__GHSA-ID.md` to preserve one record per GHSA without filename collisions.
- A CNA reference whose URL points to a GHSA but whose label describes a different artifact (for example, "Patch Commit") is disclosed as a source anomaly and is not used to rename the GHSA record.
- Conflicting upstream mappings are preserved in field 2 of every affected record instead of silently attaching CVE metrics to the wrong vulnerability.
- For a published CVE, CVE List V5 CNA CVSS and CWE are the primary classification. Differing GitHub Global and Repository values remain visible with source labels.
- Rejected CVE IDs and unavailable CVE Services records are labeled explicitly and do not silently inherit CNA metrics.
- Narrative fields are condensed from the official English advisory text. Missing facts are reported as not publicly disclosed.
- A SHA is reported as a fix commit only when the advisory identifies it as a fix. A "verified fixed tree" is not treated as the vulnerability-fixing commit.
- Code excerpts come from either the official advisory or the public patch for an advisory-published fix SHA. They are evidence excerpts, not reproduction instructions.
- PR and issue links are included only when the advisory, an explicit fix section, or the fix commit subject exposes the relationship.
- npm release timestamps are supplemental public-registry evidence and are omitted when they cannot be matched exactly.

## Reproduction

```powershell
python .\analyze_openclaw_advisories.py `
  --summary-json .\openclaw_advisory_summary.json `
  --snapshot-csv .\openclaw_advisories.csv `
  --raw-json .\openclaw_advisories_raw.json

python .\reconcile_openclaw_cves.py

python .\collect_openclaw_cve_records.py --refresh-cve-search --refresh-nvd

python .\collect_openclaw_vulnerabilities.py --output .\cve
```
